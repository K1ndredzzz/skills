# GIS、几何、渲染与验收

## 1. 准备可重现输入

对已有 DEM、RGB、行政边界、水面／河流和地名数据检查范围、CRS、日期、单位及 NoData。记录实际文件路径、图层、源要素 ID 与哈希。数据只读，处理结果放入新地区命名空间；大栅格按窗口读取，避免为了小区域加载整省。

使用适合目标区域的米制投影。几何经纬度、投影坐标、局部坐标及网页单位之间有明确变换，不拿经纬度度数直接作为网格米数。矢量与栅格先在同一 CRS 中对齐。

GIS 输出至少区分：原始采样高程、量化地形、可见地表／水床修正、有效掩膜、影像有效掩膜、水体掩膜、保护掩膜和源地物记录。用同一仿射变换和格距生成对齐数组；NoData 不当作零高程、黑色地表或可种树位置。

DEM 可按目标格距做有效像元加权采样；RGB 连续颜色与分类／有效掩膜采用各自适合的重采样规则。保留区域内真实影像缺失并说明显示方式，除非任务要求补洞。统计本地区缺失率，不能沿用全省的百分比。

## 2. 冻结自然轮廓

将候选轮廓与 DEM 阴影、水系和核心地物叠加检查，确认有效且不自交。平滑属于草稿阶段；正式轮廓冻结为 GeoJSON，记录 CRS、平滑来源和哈希。省界求交仅在本次范围有该约束时执行。

统一记录像元中心／all-touched 等栅格化规则。各档模型、底座、水面和静态图复用同一基础有效掩膜，不能各自做近似裁切。连续轮廓与阶梯外缘的偏差应按网格说明，而非宣称完全无误差。

## 3. 几何与量化

体素地形只生成外露顶面、相邻高差台阶、外缘墙和底面，避免分配整个三维实体体素数组。相同高度、颜色和朝向的面可合并；法线保持硬边。平滑地形沿用高度网格与纹理流程，别为了复用体素代码强制量化。

量化公式、基准面和舍入规则固定并写入元数据，例如以零为基准的 `step * rint(height / step)`。最近舍入的误差上限约为半个步长；LOD 合并必须使用同一量化参数。切勿只改配置中的 `heightStepM`，却仍在合并、导出或验证中使用旧的 20 米常量。

底座底面低于实际最低可见地形，切面风格与真实裸岩区分；不把棕色底座画成经过测量的地层。保留 canonical 1 倍地形，离线展示倍数与网页显示倍数单独设置。

## 4. 水体与地名

优先用源水面多边形，河道线作为补充。需要缓冲加宽时记录它是制图宽度；检查像元化后支流、洲滩、分流和汇口是否仍符合源拓扑。

湖泊／水库可依据可信资料或稳健水面估计设同一水平面，限制在源水体掩膜内。流动河流沿程变化，不能套用整库平面规则。若为消除穿地调整可见水床，保存修正前后数组、范围、数量与最大改变量，原始地形不被静默改写；杜绝挖穿相邻岸地。

地名保留来源、坐标和类别；没有现成可靠名称不编造。源名称与手工补充的已核实名称分开记录。标签贴合各档实际表面；水面已在模型内时，避免网页重复叠加另一条穿地河流。

## 5. 多视角 Blender

为每个视角保存方位、俯视角、范围、夸张倍数、相机矩阵、标注投影、指北针、配方哈希和场景。正交画面要用实际 Blender API 的宽高定义适配横纵包围范围，不能仅按一个轴取景；以边缘地物实测是否出框。

在现有四川项目中优先复用 1600 像素预览、6000 像素最终图与中文后期合成。用户未指定时可按设备和用途调整；标明“6000 像素宽”指原始渲染还是增加页眉页脚后的成图。

先按代表镜头比较风格，再检查所有最终相机的预览。实际打开图片查看地形、水系、纹理方向、遮挡、标签重叠与整体构图；配方或输入变更后重新检查受影响预览。可由执行者完成检查，不额外制造审批要求。

逐张渲染控制显存；先检测当前 GPU 能力。现有 RTX 3050 4GB 曾使用 Cycles／OptiX、预览 32 与最终 64 samples 加降噪，属于起始配置，不是所有设备标准。只有明确显存／分配失败才保持精度改用 CPU；脚本、数据、相机错误应先修复，不能用无限重试掩盖。

离线标签先做场景射线遮挡，再做像素空间避让；重要名称可用引线，但不要移动源地物。指北针从当前相机投影真实北向生成，归一化投影坐标需要先乘图像宽高再计算像素角度。中文字体在本机发现或明确指定，检查最终图无缺字。

## 6. 配方与检查记录

配方哈希覆盖有效配置、正式轮廓、输入派生数组、色板、装饰布局和实际调用的算法脚本。缓存命中必须同时确认配方与产物存在；不因文件名相同直接跳过已改变的场景。

最低验收内容：

- 范围／轮廓：核心位置在内部，边缘未剪断要解释的关系，所有档位复用同一有效区域。
- 数据／几何：高程有效、量化误差符合方案、法线与三角形绕序正确、底座未穿地、修正与原始数据分离。
- 水系：按每条源河段查连续性与汇流关系；水面贴地／水床关系可解释，没有横穿山体或无依据连接。
- 图片：方向、相机、指北针、标注、实际尺寸、显示网格和倍数一致；文字与装饰无明显遮挡。
- 场景：用 Blender 重新打开保存的场景，检查相机和角色，纹理打包或可解析，不只确认 `.blend` 文件存在。
- 回归：旧区域目录及共享配置原有记录保持，非本次目标的模型／图片不重新生成。

脚本验证可计算像元覆盖、误差、源要素匹配、场景属性与最终图片尺寸；配合目视检查，不用“程序无异常”代替视觉验收。
